# PortPulse AI — Container Congestion Predictor & Port Operations Optimiser

> **ElevateX · AI Track · Bob AI Hackathon**

PortPulse AI is a 72-hour San Pedro Bay operations cockpit that connects vessel arrivals, congestion forecasting, physical capacity, berth/crane optimisation, routing decisions and an agentic supervisor interface.

## Problem

San Pedro Bay needs a unified operational view connecting vessel arrivals, berth/crane capacity and congestion. PortPulse AI turns those signals into a forecast, identifies the binding resource, computes a physically valid schedule and produces a 72-hour operating plan.

## Solution

```text
Real POLB capacity + DEMO_AIS + weather
                 ↓
          SimPy / data context
                 ↓
    LightGBM + Isolation Forest
                 ↓
      Risk / hotspot attribution
                 ↓
          OR-Tools CP-SAT
                 ↓
      Routing + 72-hour plan
                 ↓
          IBM Bob via MCP
                 ↓
     Supervisor-facing briefing
```

**Architectural rule:** IBM Bob is the agentic interface, not the scheduler. OR-Tools creates the constrained berth/crane schedule; Bob invokes the engines through MCP and explains validated outputs. If Bob is unavailable, only a deterministic engine-derived briefing is used. There is no Claude or other external-LLM fallback.

## Core capabilities

| Capability | Implementation |
|---|---|
| Congestion prediction | LightGBM point + 10th/90th percentile forecasts at 24/48/72h |
| Disruption detection | Isolation Forest + data-error / weather / bunching / outage classification |
| Hotspots | Composite risk score + binding resource attribution |
| Berth & crane planning | OR-Tools CP-SAT BAP/QCAP + hard physical constraints + FIFO baseline |
| Routing | DIVERT / SLOW_STEAM / PRIORITY_WINDOW / HOLD with sustained-congestion checks |
| 72h plan | 12 × 6-hour shifts with provenance and confidence |
| What-if | Crane/productivity and operational stress scenarios |
| Agent | IBM Bob through MCP: 11 operational tools, resources and prompts |

## Data honesty

- **Real:** Port of Long Beach terminal/berth/crane capacity from published fact sheets.
- **Synthetic demo layer:** clearly labelled `DEMO_AIS` vessel queue and 14-day operational history generated by SimPy.
- **Real-data replacement path:** NOAA AccessAIS pipeline maps real exports into the same congestion schema.
- **Weather:** Open-Meteo wind/gust/wave/visibility observations.
- **Benchmark:** BTS PPFSP parser is available as a validation path.

The hybrid strategy is deliberate: public sources do not expose a complete live terminal TOS feed.

## Run locally

```bash
git clone https://github.com/Aryan-B-Parikh/bob-ai-hackathon-elevatex.git
cd bob-ai-hackathon-elevatex
createdb -U postgres portflow

cd src/backend
uv sync --python 3.11
cp .env.example .env
# Set DATABASE_URL and, for agentic mode, BOB_API_KEY.
uv run python -m app.seed
uv run uvicorn app.main:app --reload --port 8000

# second terminal
cd ../frontend
npm install
npm run dev
```

Open `http://localhost:5173`.

## IBM Bob integration

Register `src/backend/app/mcp_server.py` with IBM Bob. Bob can call the forecasting, hotspot, anomaly, CP-SAT, routing, scenario, vessel, terminal and plan tools directly. The dashboard's Bob AI surface can also invoke the real Bob agent. Tool-call metadata is returned for auditability.

See [`docs/bob-mcp.md`](docs/bob-mcp.md).

## Submission scope

The MVP is intentionally one complete decision loop:

**observe → predict → explain risk → optimise → route → plan → Bob**

Full live TOS/EDI integration, port-wide coverage, continuous online retraining, enterprise authentication and distributed scheduling are explicitly deferred to Phase 2. See [`docs/submission-scope.md`](docs/submission-scope.md).

## Performance limitation

This is a hackathon prototype, not a production dispatch system. Cold forecasting is approximately **11s** and a cold full plan approximately **20–30s**; warm process-cached requests are approximately **1s**. The demo should prewarm the engines.
