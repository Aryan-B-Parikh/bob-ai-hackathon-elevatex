## Important fixes completed

### Data pipeline

- Vessel schedule upload now creates real `VesselCall` rows and `EtaRevision` history, validates destination zones, deduplicates IMO/voyage pairs, records rejected rows and triggers replanning.
- Uploads are capped at 10 MB.
- Open-Meteo weather is invoked at startup and through `/api/weather/refresh`.
- BTS PPFSP parsing is exposed as a benchmark/validation endpoint.
- Data quality now joins vessels using `Terminal.zone_code == VesselCall.dest_zone_code`, so an empty join cannot masquerade as 100% completeness.

### Dashboard

The cockpit now includes the core presentation surfaces required by the specification: interactive congestion heatmap, terminal cards and drill-down, forecast uncertainty, 72-hour Gantt with tidal context, routing recommendations, scenario analysis, quality/ingestion and Bob AI.

A deeper port→terminal→berth→vessel navigation hierarchy and richer scenario-comparison workflows remain optional polish, not blockers for the L1 MVP.

### Anomaly detection

Isolation Forest evaluates a rolling 72-hour window and classifies meaningful conditions including `BUNCHING`, `OUTAGE`, `YARD_SATURATION`, `WEATHER`, `DATA_ERROR` and `VARIANCE`, with a minimum-history guard and confidence score.

### Plan provenance

`OperationsPlan` and the plan summary carry the actual `forecast_run_id`, `optimiser_run_id` and `model_version`. `GET /api/plan` serves the latest persisted plan when available instead of rebuilding a plan with null provenance.

### IBM Bob

IBM Bob is the **only agent provider**. Bob connects to the MCP server and can execute the real forecasting, anomaly, hotspot, CP-SAT, routing, scenario, vessel, terminal and plan tools. If Bob is unavailable, only a deterministic engine-derived briefing is used. There is **no Claude or other external-LLM fallback**.

## Data strategy

- **Real:** Port of Long Beach terminal/berth/crane capacity from published fact sheets.
- **Synthetic demo:** clearly labelled `DEMO_AIS` vessel queue and operational history generated by SimPy.
- **Replaceable real path:** NOAA AccessAIS can populate the same congestion schema.
- **Weather:** Open-Meteo wind/gust/wave/visibility.
- **Benchmark:** BTS PPFSP parser available for validation.

The hybrid strategy is intentional because public sources do not expose a complete live terminal TOS feed.

## Performance limitation

This is a hackathon prototype rather than a production dispatch system. Cold LightGBM forecasting is approximately **11 seconds** and a cold full plan approximately **20–30 seconds**. Process caching brings warm requests to approximately **1 second**. The demo should prewarm the engines.

## Scope lock

The submission intentionally prioritizes one complete decision loop over breadth. Phase-2 items are deferred:

- full live TOS / EDI / event-stream integration
- complete port-wide berth estate
- continuous online model retraining
- enterprise authentication / multi-tenant deployment
- distributed enterprise-scale scheduling
